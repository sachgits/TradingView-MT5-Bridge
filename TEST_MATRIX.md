# Test matrix

Two layers: the automated suite (`python -m pytest Trading_Bridge_Source/tests`, 167 tests) pins the contract and the safety rules; the manual procedure below exercises the same rules against a real terminal on a **demo** account.

## Automated suite

| File | Pins down |
|---|---|
| `tests/test_contract.py` | Retcode meanings (including MT5 success codes), action aliases, envelope key order, file-suffix coverage |
| `tests/test_schema_validation.py` | Legacy text, truncated JSON never parsed as legacy, size/distance canonicalization, ATR defaults, breakeven/trailing sub-distances, strict vs permissive, every skipped action refused, malformed ladders warn-only |
| `tests/test_store.py` | FIFO single-use claims, terminal states, expiry, revive rules, dedup window, event ordering, metrics aggregates, the `file_intake` claim register, `inbox_adoption` idempotence and persistence |

| `tests/test_journal.py` | Trade-journal records reduced to a lean EA command (long→buy/short→sell, `sizing.lots`, absolute `setup.stop`/`target` → `price_distance` gaps, ATR and `pip_distance` fallbacks, breakeven `trigger_r`), the inbox payload never mutated, wrong-side stop and stopless-entry refused, `status` gating (entry/close/skip), the `journal_max_age_seconds` freshness gate in submit and preview (and that native commands are exempt), and an in-place journal update detected as a duplicate rather than a second order |

## Manual demo procedure

Run each step on a demo account and confirm the board's Signals row, the drawer timeline, the MT5 Experts journal and the broker retcode.

1. **Legacy compatibility** - `{"signal":"BUY SL=50 TP=100 LOT=0.01"}` → queued with a `legacy` warning; symbol comes from the EA's chart.
2. **Structured entry** - `{"request_id":"demo-001","action":"buy","symbol":"EURUSD","size":{"value":0.01,"unit":"lots"},"stop_loss":{"unit":"points","value":200},"take_profit":{"unit":"points","value":400}}` → executed, retcode labelled on the board.
3. **Duplicate protection** - drop the same command under a second filename within the dedup window → `duplicate`, one trade, both copies `.processed`. Re-drop the *identical* file at the same path → skipped by the intake register, no second signal at all.
4. **Idempotency key** - repost the same `request_id` after a cancel → revived row, still one trade.
5. **Refusal** - `{"action":"buy","symbol":"EURUSD"}` in strict mode → `rejected` with the size reason; nothing dispatched.
6. **Corrupt file** - write `{"action": "buy", "sym` → `.invalid` copy, no trade, event on the board, original untouched in the inbox.
7. **Pause** - pause dispatch, drop a valid file, poll → EA receives the idle envelope with `reason: paused`; resume → it dispatches.
8. **Expiry** - pause, dispatch nothing, wait past the dispatch timeout → `expired` with a board toast; **Requeue** puts it back, **Retry as new** mints a fresh id.
9. **Broker rejection** - force a failure (e.g. an impossible volume) → `failed` with the broker retcode and its meaning in the histogram.
10. **Late ack** - acknowledge after expiry → the row becomes `executed`; the trade that happened is the truth.
11. **Settings** - change the watch interval on the board and confirm `/api/v1/watcher` reflects it; submit an out-of-range batch and confirm nothing is applied.
12. **Restart survival** - restart the bridge with a queued signal present → still queued, still dispatched exactly once.
13. **Read-only inbox** - after a mixed batch (good, rejected, corrupt), compare the inbox against a snapshot taken before: same names, same sizes, same mtimes, same bytes. All markings are in `data\intake\`. Optionally deny write permission on the inbox for your user and confirm intake still works.
14. **Folder separation** - start with `--data` pointing at the inbox (or a subfolder of it) → the bridge refuses to start and says why.
15. **Switching the inbox** - put a `.json` file in a second folder, change **Inbox folder (read-only)** on the board and save → the Intake panel shows the new folder, `Adopted on switch` counts the file, and nothing is queued. Rewrite that file with different bytes → still nothing is queued. Drop a new file → it is consumed normally. Restart → the new inbox and the adoption both come back.
16. **Trade-journal record** - drop a fresh journal record (`pair`/`direction`/`setup`/`sizing`, `status: triggered_active`, `lifecycle.triggered_at` = now) → it queues as a lean `buy`/`sell` with `size` in lots and `stop_loss`/`take_profit` as `price_distance` gaps, `request_id` = `"{id}:{action}"`, and warnings that EA v6.5 ignores `price`. Rewrite the same file in place (exit price filled, `status: closed`) → the entry is a `duplicate`; a `closed` status maps to a distinct `close_position`. Set `triggered_at` more than `journal_max_age_seconds` in the past → `rejected` as stale, nothing queued.
17. **Pending placement** - send `{"action":"buy_stop","symbol":"EURUSD","size":{"value":0.01,"unit":"lots"},"price":1.1200,"price_unit":"price","stop_loss":{"unit":"points","value":200},"take_profit":{"unit":"points","value":400}}` → executed, the order appears in MT5 and on the Positions tab's pending table. Repeat with `price_unit":"points"` and a signed `price` (e.g. `120` above Ask for a buy) and confirm the offset direction; a `buy_stop_limit` additionally needs `stoplimit`; an `expiration` in ISO or MT5 form is honoured, a bad one is refused `-43`.
18. **Pending management** - `{"action":"modify_pending","order_ticket":<ticket>,"price":1.1250}` moves the order; `{"action":"cancel_pending","order_ticket":<ticket>}` deletes it. A ticket the bot does not own (wrong magic) or that no longer exists returns `-41`, not a silent success.
19. **Account snapshot & Positions tab** - with `account_poll_seconds > 0` and the queue empty, let the EA idle-poll → it reports `ACCOUNT SNAPSHOT`, the Positions tab fills in balance/equity/margin KPIs and both tables, and no ledger row is created. Click **Refresh** → a new snapshot is forced on the next idle poll even if the current one is still fresh. Drop a trade while a snapshot is due → the trade is dispatched first, the snapshot waits. Pause dispatch → no snapshot is injected either. Restart the bridge → the last snapshot persists (runtime table) until the next poll replaces it.
20. **Settings survive the refresh** - on the Settings tab, type a value into a field (e.g. the account interval) and leave the cursor there through at least one background refresh (~5 s) → the typed text and the focus are untouched; the server's stored value is shown only for fields you have not edited. **Discard** rebuilds the form from the server; **Save** applies and rebuilds.

## Commands the EA does not execute

`close_positions` (use `close_all`), `modify_position` (use `modify`), `close_pending` (use `cancel_pending`) and `reverse` are refused at intake with the reason the EA would have skipped them, so a command can never be acknowledged `SKIPPED` silently.

The six pending-order types (`buy_limit`, `sell_limit`, `buy_stop`, `sell_stop`, `buy_stop_limit`, `sell_stop_limit`) and `cancel_pending` / `modify_pending` were on that list until EA v6.5 implemented them; they are now real executed actions.
